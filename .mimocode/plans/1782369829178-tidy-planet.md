# 容灾方案：Supabase 实时复制

## 现状

- **主服务器**: Mac 上 SQLite (`data.db`)，端口 3001
- **客户端**: IndexedDB，每 4 秒同步到主服务器
- **风险**: Mac 故障 → 数据丢失，无法同步

## 架构

```
客户端 (IndexedDB)
    ↕ 每 4 秒同步
主服务器 (Mac SQLite:3001)
    ↕ 每次 push 后实时写入
Supabase (PostgreSQL) ← 容灾目标
    ↕ 恢复时读取
备用服务器 / 直连 Supabase
```

正常运行时：客户端 ↔ Mac 服务器（现有流程不变）
Mac 故障时：客户端切换 serverUrl → 备用服务器或直接连 Supabase REST API

## 实现步骤

### Step 1: Supabase 建表

在 Supabase SQL Editor 执行建表脚本，字段与 SQLite 对齐：

```sql
-- 用户表
CREATE TABLE IF NOT EXISTS users (
  id TEXT PRIMARY KEY,
  phone TEXT UNIQUE NOT NULL,
  password TEXT NOT NULL,
  nickname TEXT DEFAULT '',
  pending_link_list TEXT DEFAULT '[]',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 标签表
CREATE TABLE IF NOT EXISTS tags (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  color TEXT DEFAULT '#3B82F6',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ
);

-- 题目表
CREATE TABLE IF NOT EXISTS questions (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  question_image_url TEXT,
  answer_image_url TEXT,
  layout_type INTEGER DEFAULT 0,
  user_comment TEXT DEFAULT '',
  semantic_summary TEXT DEFAULT '',
  ai_metadata TEXT DEFAULT '{}',
  book_name TEXT DEFAULT '',
  page_number TEXT DEFAULT '',
  question_number TEXT DEFAULT '',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ,
  purged_at TIMESTAMPTZ
);

-- 题目标签关联
CREATE TABLE IF NOT EXISTS question_tags (
  question_id TEXT NOT NULL REFERENCES questions(id),
  tag_id TEXT NOT NULL REFERENCES tags(id),
  PRIMARY KEY (question_id, tag_id)
);

-- 试卷表
CREATE TABLE IF NOT EXISTS papers (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ
);

-- 试卷题目关联
CREATE TABLE IF NOT EXISTS paper_questions (
  paper_id TEXT NOT NULL REFERENCES papers(id),
  question_id TEXT NOT NULL REFERENCES questions(id),
  order_num INTEGER DEFAULT 0,
  PRIMARY KEY (paper_id, question_id)
);

-- 相似题关联
CREATE TABLE IF NOT EXISTS similar_question_links (
  question_id TEXT NOT NULL REFERENCES questions(id),
  similar_question_id TEXT NOT NULL REFERENCES questions(id),
  user_id TEXT NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ,
  PRIMARY KEY (question_id, similar_question_id)
);

-- 专题表
CREATE TABLE IF NOT EXISTS topics (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  deleted_at TIMESTAMPTZ
);

-- 专题题目关联
CREATE TABLE IF NOT EXISTS topic_questions (
  topic_id TEXT NOT NULL REFERENCES topics(id),
  question_id TEXT NOT NULL REFERENCES questions(id),
  order_num INTEGER DEFAULT 0,
  teacher_comment TEXT DEFAULT '',
  PRIMARY KEY (topic_id, question_id)
);

-- 笔记版本
CREATE TABLE IF NOT EXISTS question_notes (
  id TEXT PRIMARY KEY,
  question_id TEXT NOT NULL REFERENCES questions(id),
  note_image_url TEXT,
  label TEXT DEFAULT '',
  text_note TEXT DEFAULT '',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 待处理照片
CREATE TABLE IF NOT EXISTS pending_photos (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  image_url TEXT,
  group_id TEXT DEFAULT 'group_1',
  processed INTEGER DEFAULT 0,
  question_id TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_tags_user ON tags(user_id);
CREATE INDEX IF NOT EXISTS idx_questions_user ON questions(user_id);
CREATE INDEX IF NOT EXISTS idx_papers_user ON papers(user_id);
CREATE INDEX IF NOT EXISTS idx_topics_user ON topics(user_id);
CREATE INDEX IF NOT EXISTS idx_question_notes_question ON question_notes(question_id);
CREATE INDEX IF NOT EXISTS idx_pending_photos_user ON pending_photos(user_id);
```

### Step 2: 服务端新增 Supabase 复制模块

新建 `question-bank-server/replicate.js`：

- 使用 `@supabase/supabase-js` 客户端
- 环境变量：`SUPABASE_URL`, `SUPABASE_ANON_KEY`（或 SERVICE_ROLE_KEY）
- 核心函数：`replicateToSupabase(userId, payload)` — 在每次 sync push 成功后调用
- 批量 upsert 每个表的数据（Supabase 支持 `upsert`）
- 错误不阻塞主流程（try-catch，仅 console.warn）

### Step 3: 服务端修改 sync 路由

修改 `question-bank-server/routes/sync.js` 的 `POST /push`：

```js
// 在 transaction() 执行完毕后，异步触发复制
const { replicateToSupabase } = require('../replicate');
// ...
transaction();
// 异步复制，不阻塞响应
replicateToSupabase(req.userId, { tags, questions, papers, similar_links, pending_link_list }).catch(console.warn);
res.json({ success: true, now: nowIso(), applied });
```

### Step 4: 新增恢复 API

新建 `question-bank-server/routes/recovery.js`：

- `POST /api/recovery/sync-to-supabase` — 全量推送到 Supabase（初始化或修复时用）
- `GET /api/recovery/status` — 显示 Supabase 连接状态 + 最后同步时间

### Step 5: 客户端恢复入口

在 `index.html` 设置 Tab 添加「容灾」区域：

- 显示 Supabase 同步状态
- 「全量同步到云端」按钮（触发 `/api/recovery/sync-to-supabase`）
- 「切换到备用服务器」输入框 + 保存按钮（修改 `serverUrl`）

## 恢复流程（Mac 故障时）

1. 在任意机器启动备用服务器（连接同一个 Supabase）
2. 打开 App → 设置 → 修改 serverUrl 为备用服务器地址
3. 点击「从云端下载」→ 数据从 Supabase 恢复到本地

## 验证方式

1. 配置 Supabase 环境变量，启动服务器
2. 客户端创建几道题，观察 Supabase Dashboard 数据是否实时写入
3. 停止 Mac 服务器
4. 在另一台机器启动备用服务器（连同一 Supabase）
5. 客户端修改 serverUrl → 点击「从云端下载」→ 验证数据完整恢复
