# 单元测试 + 性能优化方案

## 一、单元测试的意义

1. **回归保护**：修改代码后自动验证现有功能不被破坏
2. **文档作用**：测试用例即函数的使用文档，展示输入/输出/边界
3. **重构信心**：有测试覆盖的代码可以安全重构
4. **调试效率**：定位问题到具体函数，而非整个应用
5. **代码质量**：迫使函数职责单一、接口清晰

## 二、单元测试方案

### 框架选择：Vitest

- 零配置启动，原生 ESM 支持
- 速度快（比 Playwright E2E 快 10-50 倍）
- 与现有 Playwright E2E 测试互不冲突

### 新建文件

| 文件 | 用途 |
|------|------|
| `vitest.config.js` | Vitest 配置 |
| `tests/unit/db-utils.spec.js` | 纯逻辑函数测试（15个，无 mock） |
| `tests/unit/db-sync.spec.js` | 远程同步逻辑测试（mock fetch） |
| `tests/unit/db-operations.spec.js` | IndexedDB CRUD 测试（mock localForage） |

## 三、性能优化方案

### Fix 1：`_buildTagIndex()` 加缓存（最高收益）

**问题**：每次调用都全表扫描 2 个 store，`dbGetPaperQuestions()` 在循环内每轮调用

**方案**：
- 引入模块级缓存 + 脏标记
- 写操作调用 `_invalidateTagIndex()`
- `dbGetPaperQuestions()` 循环外只调一次

**文件**：`www/db.js:47-67`

### Fix 2：`_needsNormalization()` 避免 JSON.stringify（高收益）

**问题**：对包含 base64 图片的对象做 JSON.stringify，100KB+ 对象序列化两次

**方案**：改为按字段引用比较（`!==`），只检查 normalize 可能修改的字段

**文件**：`www/db.js:216-219`

### Fix 3：`dbGetPaperQuestions()` 批量查询

**问题**：逐个 `await dbQuestions.getItem()`，N 题 N 次异步调用

**方案**：用 `Promise.all` 并行获取所有题目

**文件**：`www/db.js:604-620`

### Fix 4：`dbCreatePaper()` 修复 race condition

**问题**：第 583-588 行用 `setTimeout(50ms)` 等待 promise resolve，不可靠

**方案**：收集所有 promise 后用 `Promise.all` 等待

**文件**：`www/db.js:574-595`

### Fix 5：`refreshAll()` 并行加载

**问题**：串行执行 tag/question/paper 加载

**方案**：改为 `Promise.all` 并行

**文件**：`www/index.html:1014`

### Fix 6：`dbBuildSyncPayload()` 并行化

**问题**：串行处理所有 store 的 normalize + collect

**方案**：并行读取各 store，串行上传图片（避免服务器并发限制）

**文件**：`www/db.js:679-772`

### Fix 7：`importAllData()` 批量写入

**问题**：逐个 `await setItem`，500 题 500+ 次写入

**方案**：用 `Promise.all` 批量写入各 store

**文件**：`www/db.js:1046-1059`

## 四、实施顺序

1. 安装 Vitest 依赖
2. 创建 `vitest.config.js`
3. 写 Layer 1 纯逻辑函数测试（不改生产代码）
4. 写 Layer 2/3 测试（mock 依赖）
5. 修复 Fix 1（`_buildTagIndex` 缓存）
6. 修复 Fix 2（`_needsNormalization` 优化）
7. 修复 Fix 4（race condition）
8. 修复 Fix 3（批量查询）
9. 修复 Fix 7（批量导入）
10. 修复 Fix 5/6（并行化）
11. 跑 E2E 回归测试

## 五、验证步骤

1. `npm run test:unit` — 单元测试全部通过
2. `npm run test:e2e:pw` — E2E 测试全部通过
3. 手动验证：创建 50+ 题目、创建试卷、刷新页面，观察响应速度

## 六、风险评估

| 修改 | 风险 | 缓解措施 |
|------|------|----------|
| `_needsNormalization` 改为字段比较 | 中 | 新字段需同步更新比较列表 |
| `_buildTagIndex` 缓存 | 低 | 写操作必须调用 `_invalidateTagIndex()` |
| `dbGetPaperQuestions` 批量查询 | 低 | IndexedDB getItem 并发安全 |
| `dbCreatePaper` 修复 race | 低 | Promise.all 是标准做法 |
| `importAllData` 批量写入 | 低 | IndexedDB 无事务依赖 |
| Vitest 测试文件 | 无 | 纯新增文件 |
